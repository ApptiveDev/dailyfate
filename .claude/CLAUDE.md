# DailyFate - 사진 미션 일력 앱

## 앱 개요

DailyFate는 매일 사진 미션을 제공하고, 사용자가 해당 미션에 맞는 사진을 촬영하여 기록하는 앱입니다.
매달 말일에는 한 달 동안 업로드한 사진들을 조합하여 **월별 앨범**을 생성해주는 것이 핵심 기능입니다.

---

## 핵심 가치

- **단순함** - 복잡한 기능 없이 "미션 확인 → 사진 촬영 → 기록" 플로우에 집중
- **여백의 미** - 넉넉한 여백, 큰 컴포넌트, 시원한 레이아웃
- **일상 기록** - 사소한 순간들을 모아 한 달의 추억으로 완성

## 아키텍처·상태관리 원칙

### UI/화면 구조 패턴

본 앱은 **MVVM에 가까운 구조**를 따른다. View = 화면 컴포넌트, ViewModel = Custom Hooks + 전역 상태.

| 패턴 | 한 줄 요약 | 본 앱 적용 |
|------|------------|------------|
| **MVC** | Model-View-Controller, 뷰와 로직 분리 | 사용하지 않음 (View-Controller 비대화 우려) |
| **MVP** | Presenter가 View·Model 중개 | 사용하지 않음 |
| **MVVM** | View는 ViewModel만 참조, 단방향·선언적 UI에 적합 | **기준 패턴** – 화면 = View, 로직·상태 = Hooks/Context |
| **MVI** | Intent → Model 갱신 → View, 엄격한 단방향 | 필요 시 일부 화면에서 Intent/Reducer 형태 적용 |

- **화면(Page)**  
  - UI만 담당. 비즈니스 로직·데이터 fetch는 Custom Hooks나 Context에 위임.
- **Custom Hooks**
  - `useTodayMission()`, `useMonthlyAlbum()`, `usePhotoManagement()`, `useModalState()`, `useAppBootstrap()` 등으로 화면 로직·상태를 묶어 ViewModel 역할을 한다.
- **전역 상태**
  - Context Provider (`MissionProvider`, `PhotoProvider`, `AuthProvider`)로 한 곳에서 관리. 서버/캐시는 TanStack Query(React Query) 등으로 분리 권장.

### 상태관리 원칙

1. **단일 진실 공급원 (Single Source of Truth)**  
   같은 데이터는 한 곳(스토어/Context/서버 캐시)에서만 “진실”로 두고, 나머지는 구독·파생만 한다.

2. **단방향 데이터 흐름 (Unidirectional Data Flow)**  
   `사용자 액션 → 액션/이벤트 → 상태 갱신 → 뷰 리렌더`. 뷰가 전역 상태를 직접 변경하지 않는다.

3. **예측 가능한 상태 변경**  
   상태는 액션/이벤트를 통해서만 바꾸고, 갱신 로직을 한곳에 두어 디버깅·재현이 쉽게 한다.

4. **파생 상태는 계산으로**  
   원본 상태만 저장하고, 필터 목록·통계 등은 선택자(selector)나 `useMemo` 등으로 계산한다. 중복 저장을 피한다.

5. **관심사 분리**  
   - **UI 상태**: 모달 열림/닫힘, 탭 인덱스 등 → 로컬 state 또는 해당 화면 Context.  
   - **도메인 상태**: 미션 목록, 사진 목록 등 → 전역 Context/Zustand.  
   - **서버/캐시 상태**: API 응답, 캐시 무효화 → React Query 등 전용 라이브러리.

### 폴더·레이어 구조

- **데이터 레이어** (`src/data/`)
  - Mock 데이터, 유틸리티 함수 등 데이터 관련 로직
- **Hooks 레이어** (`src/hooks/`)
  - Custom Hooks로 ViewModel 역할 수행
  - `useAppBootstrap`, `useTodayMission`, `useMonthlyAlbum`, `usePhotoManagement`, `useModalState` 등
- **Providers 레이어** (`src/providers/`)
  - Context Provider로 전역 상태 관리
  - `AuthProvider`, `MissionProvider`, `PhotoProvider`
- **페이지 컴포넌트** (`src/components/pages/`)
  - 화면 단위 View 컴포넌트 (UI만 담당, 로직은 훅에 위임)
- **공통 UI** (`src/components/ui/`)
  - 버튼, 카드, 스택 등 재사용 컴포넌트
- **라우트** (`app/`)
  - Expo Router 라우팅, Provider 조합, 최소한의 조합 로직만 포함

## 유저 스토리

### 핵심 유저 스토리

1. **미션 확인** - 사용자는 앱을 열면 오늘의 사진 미션을 확인할 수 있다
2. **사진 촬영** - 사용자는 미션에 맞는 사진을 촬영하거나 갤러리에서 선택할 수 있다
3. **미션 완료** - 사용자는 사진을 업로드하여 오늘의 미션을 완료할 수 있다
4. **기록 확인** - 사용자는 캘린더에서 과거에 업로드한 사진들을 확인할 수 있다
5. **통계 확인** - 사용자는 월별 미션 성공률과 연속 달성 기록을 확인할 수 있다
6. **월별 앨범** - 사용자는 매달 말일에 자동 생성된 월별 앨범을 받을 수 있다

### 상세 유저 스토리

| ID | 스토리 | 우선순위 |

## 페이지 구성

### 공통: 하단 탭 네비게이션

**모든 화면**에는 하단(또는 상단) 탭으로 아래 네 화면으로 이동할 수 있다.

| 탭 | 이동 대상 |
|----|-----------|
| 메인 | 오늘 미션 (TodayMissionPage) |
| 월별 통계 | 월별 통계 목록 (MonthlyAlbumPage) |
| 캘린더 | 캘린더 뷰 (CalendarPage) |
| 설정(프로필) | 설정·프로필 페이지 (SettingsPage) |

### 1. 메인 페이지 (TodayMissionPage)

**목적**: 오늘의 미션 확인 및 사진 업로드

```
┌─────────────────────────────┐
│ [Logo]              [설정] │  ← 헤더 (상단 52%)
│                             │     배경: #000000
│   1월 16일 (목)             │
│                             │
│   오늘의 그림자             │  ← 미션 텍스트 (42px, Bold)
│                             │
├─────────────────────────────┤
│                             │  ← 하단 (48%)
│   MISSION                   │     배경: #FFFFFF
│                             │
│       ┌─────────┐           │
│       │    +    │           │  ← 원형 버튼 (200x200)
│       └─────────┘           │     미완료: + 아이콘
│                             │     완료: ✓ 아이콘
└─────────────────────────────┘
```

**구성 요소**:
- 상단 영역 (Black, 52%)
  - 로고 아이콘 (command)
  - 설정 버튼
  - 날짜 표시 (월/일/요일)
  - 미션 텍스트
- 하단 영역 (White, 48%)
  - 상태 레이블 (MISSION / COMPLETED)
  - 원형 액션 버튼

### 2. 월별 통계 페이지 (MonthlyAlbumPage)

**목적**: 월별 미션 달성 현황 확인

```
┌─────────────────────────────┐
│ 나의 기록              [설정]│  ← 헤더
│ 월별 통계                   │
├─────────────────────────────┤
│ ┌───────────────────────┐   │
│ │ 2026년                │   │  ← 월별 카드 (겹치는 스택)
│ │ 1월           성공률  │   │
│ │               87.5%   │   │
│ │ ⚡ 연속 12일      →   │   │
│ └───────────────────────┘   │
│   ┌───────────────────────┐ │
│   │ 12월                  │ │
│   └───────────────────────┘ │
│     ┌───────────────────────┐
│     │ 11월                  │
└─────┴───────────────────────┘
```

**구성 요소**:
- 헤더
  - 서브타이틀 (나의 기록)
  - 타이틀 (월별 통계)
  - 설정 버튼
- 카드 스택 (Apple Wallet 스타일)
  - 월별 파스텔 컬러 배경
  - 년/월 표시
  - 성공률 (%)
  - 연속 달성 배지
  - 상세 보기 화살표

**이동 흐름**:
- **월 카드 탭** → **캘린더 페이지(3)** 로 이동 (탭한 해당 월 기준)

### 3. 캘린더 페이지 (CalendarPage)

**목적**: 날짜별 기록 확인, 달성률 확인, 월별 앨범 생성 진입

**진입**: **[캘린더 탭]** 선택 시, 또는 **월별 통계 페이지(2)**에서 월 카드 탭 시 (해당 월로 표시)

```
┌─────────────────────────────────┐
│   2025년 1월        달성률 80%   │  ← 년·월, 달성률
├─────────────────────────────────┤
│  ┌─┬─┬─┬─┬─┬─┬─┐                │
│  │월│화│수│목│금│토│일│                │  ← 요일 행
│  ├─┼─┼─┼─┼─┼─┼─┤                │
│  │📷│📷│📷│ │📷│📷│📷│                │  ← 날짜 셀 (📷 = 사진 있음)
│  │📷│📷│ │📷│📷│📷│📷│                │
│  │...                           │
│  └─┴─┴─┴─┴─┴─┴─┘                │
│                                 │
│  [📥 이번 달 앨범 만들기]        │  ← 앨범 생성 버튼
└─────────────────────────────────┘
```

**구성 요소**:
- 헤더
  - 년·월 표시 (예: 2025년 1월)
  - 달성률 (예: 달성률 80%)
- 캘린더 그리드
  - 요일 행 (월~일)
  - 날짜 셀: 사진이 있는 날은 📷 표시, 없으면 빈 칸
- 하단
  - [📥 이번 달 앨범 만들기] 버튼

**이동 흐름**:
- **날짜 탭** → **사진 상세 페이지 (5. PhotoDetailPage)** 해당 날짜 사진 확인·관리
- **이번 달 앨범 만들기 탭** → **월별 앨범 상세 페이지 (6)** 콜라주 확인·저장·공유

### Hooks 사용 가이드

| Hook | 역할 | 사용처 |
|------|------|--------|
| `useAppBootstrap` | 앱 부팅, 온보딩, 로그인, 프로필 설정 상태 통합 관리 | `app/index.tsx` |
| `useTodayMission` | 오늘 날짜, 미션, 사진, 통계 | `app/index.tsx` |
| `useMonthlyAlbum` | 월별 앨범 year/month 네비게이션, 월별 사진/통계 | `app/index.tsx` |
| `usePhotoManagement` | 사진 캡처, 선택, 저장, 삭제 | `app/index.tsx` |
| `useModalState` | 카메라/프리뷰/상세/설정 모달 열림 상태 | `app/index.tsx` |

### Provider 사용 가이드

| Provider | 역할 | 제공 Hook |
|----------|------|-----------|
| `AuthProvider` | 인증 상태 (로그인/로그아웃) | `useAuth()` |
| `MissionProvider` | 미션 데이터 CRUD | `useMission()` |
| `PhotoProvider` | 사진 데이터 CRUD | `usePhotos()` |

### 디자인 원칙

1. **Less is More** - 불필요한 요소 제거, 핵심 기능에 집중
2. **큰 터치 영역** - 버튼 최소 44x44, 주요 버튼은 80x80 이상
3. **명확한 피드백** - 완료/미완료 상태 명확하게 구분
4. **일관된 여백** - px-6 (24px) 또는 px-8 (32px) 사이드 패딩 유지
5. **모노톤 기반** - 흑백 위주, 컬러는 포인트로만 사용
